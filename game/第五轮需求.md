## 2. 公平对决升级：两位玩家各自赚钱、各自金库、各自武器库

master 原话：公平对决应该是**两个玩家都需要赚钱买装备，各自有各自的金库和武器库**。

- 现在的问题：双人模式蓝方有独立钱包/装备/武器等级，但**赚钱任务只有红方（陈大至）一套**；AI 模式姐姐是"战后自动拿钱买装备"（sisGrow 凭空发钱），不符合"都靠赚钱任务"的公平规则。
- 整改目标：
  a) **任务系统分档案**：红方和蓝方各自有独立的赚钱任务记录（按时睡觉/拿快递/扫地/吃饭/自定义任务，各自按天计数、各自的金库）。双人模式切换操作对象（现有 activeProfile 机制）时，任务页显示的是当前档案的任务与金库；完成任务给当前档案发 R。
  b) **AI 模式姐姐也靠任务赚钱**：每场战斗之间/每日结算时，姐姐按规则自动"完成"赚钱任务（睡觉 5R、拿快递按重量 1/3/5、扫地 3R、吃饭 3R，按天各限次数），用赚到的 R 按策略买装备、升级武器——与玩家同一套经济，**不凭空发钱**；她的任务进度可在战斗菜单/姐姐页面看到。
  c) **界面**：主菜单或战斗菜单显示双方金库与装备概况（红：xxx R · 蓝：xxx R），双人模式可切到蓝方操作任务+商店+背包。
  d) 存档：红蓝各自 taskLog、r、owned、wlv、loadout；老存档合并。

## 3. 重绘素材评估与重制（写对提示词、选对模型、适配游戏）

master 反馈三类问题：**① 有些图标在游戏里太小看不清；② 有些和弟弟手绘大相径庭；③ 有些细节丢失（比如弓箭没有箭的形状了）**。要求：三个生图模型（Anima/Z-Image/Krea 2）+ qoder 识图能力，先评估外观，再重制不合格素材，优化游戏整体。

- **第一步：逐张评估**（用 Read 识图 + 对比弟弟原稿 game/ 4 张 jpg 和 icons/ 裁切）：
  - 对现有 23 张 `game/art_*.png` 逐张对照原稿：是否偏离构图/元素；关键细节是否丢失（火枪要有枪管和扳机感、弓箭必须弓+搭弦的箭、火焰箭箭头带火苗、雷电箭带闪电、盾要有盾形、瓶子要有瓶形+十字/叉号、盔甲要有块状胸甲+头盔、战马要有护面和尾盾）。
  - 在游戏 UI 实际显示尺寸下评估（商店卡片图标约 40-56px、背包/战斗徽章更小）：主体是否居中、轮廓是否清晰、有无细碎细节糊成一片。
  - 输出一份评估表：每张素材 合格/不合格 + 原因。
- **第二步：重制不合格素材**：
  - **选对模型**：动漫/插画/幻想题材优先 Anima（它理解"尾巴挂盾"这类设定）；写实/文字用 Z-Image；图生图重绘用 Krea 2（denoise 参考 0.55-0.7 保构图，0.85+ 重写）。
  - **写对提示词**：Danbooru 标签 + 自然语言混合（Anima 前缀 `masterpiece, best quality, score_7, safe, `；负面固定 `worst quality, low quality, score_1, score_2, score_3, artist name, blurry, jpeg artifacts`）；**关键细节写死位置**（如 `a bow with an arrow nocked on the string`、`flaming arrowhead`、`round shield with dragon emblem`、`armored chest with helmet`），反常识设定在负面排除常规位置；每张 3 种子抽签。
  - **适配小尺寸**：主体居中、粗轮廓、高对比、无细碎杂线；可出高清后为游戏内小图标单独裁一版简化轮廓。
  - 出图后必须 review_image.ps1 视觉审阅，对照弟弟原稿验收。
- **第三步：集成与整体优化**：
  - 替换不合格素材为 `game/art_*.png`（保持文件名不变，HTML 不用大改）。
  - 用浏览器/agent 检查游戏内实际显示：商店、背包、战斗、主菜单横幅、双头像；图标太小/太糊的，调 CSS 显示尺寸或换更简洁素材。
  - 整体视觉一致性：色调统一、边缘干净、与 UI 卡片融合。
